# Classification and Regression Study

Comparative study of symbolic and sub-symbolic machine learning techniques — **ID3 (Decision Tree)**, **Random Forest**, and a **Multi-Layer Perceptron (MLP)** — applied to a clinical vital-signs dataset. The project reconstructs a synthetic "gravity" score (regression) and its four-level severity class (classification) from sensor readings, and compares the three approaches on accuracy, generalization, interpretability, and computational cost.

This repo accompanies the paper *"Modelagem de Problemas utilizando Aprendizagem de Máquina: Análise comparativa de Algoritmos Simbólicos e Redes Neurais para Classificação de Sinais Vitais"* ([`trabalho_mlSI.pdf`](./trabalho_mlSI.pdf)), written for the Machine Learning course at UTFPR by Guilherme Peruci Felippe and Caique Ferraz Cornelio.

## Dataset

[`data.csv`](./data.csv) contains 1,500 simulated victim records with the following columns:

| Column | Description |
|---|---|
| `I` | Record index |
| `P_sist`, `P_dist` | Systolic / diastolic blood pressure (used only to derive `qPA`, not fed directly into the symbolic models) |
| `qPA` | Blood pressure quality indicator |
| `Pulse` | Heart rate (bpm) |
| `BreathFreq` | Respiratory rate (breaths/min) |
| `Gravity` | Continuous severity score (regression target) |
| `Class` | Severity class, 1–4 (`1` = critical, `2` = unstable, `3` = potentially stable, `4` = stable) |

`Gravity` and `Class` were generated by an undisclosed formula; the goal of every model here is to recover them from the vital signs alone.

## Methodology summary

- **ID3 / Decision Tree** — trained on `qPA`, `Pulse`, `BreathFreq` with a 60/40 train-test split. Hyperparameters `min_samples_split` and `max_depth` are swept to study over/underfitting before picking the optimal tree (`min_samples_split=15`, `max_depth=8`).
- **Random Forest** — same features and split, with `n_estimators`, `max_depth`, and `min_samples_split` tuned via a similar sensitivity analysis. Includes both a scikit-learn version and a from-scratch bootstrap-ensemble implementation.
- **MLP** — feature set is enriched with four engineered variables (`P_diff`, `Pressure_per_Pulse`, `Resp_Index`, and the pressure-to-pulse ratio), standardized, and split 70/30. Two heads are trained: a regression head for `Gravity` and a classification head (one-hot encoded) for `Class`.
- **Validation** — all three approaches are evaluated with K-Fold cross-validation followed by a held-out test set, using RMSE (for the regression target), accuracy, precision, recall, and F1-score (for classification).

## Results

| Model | Accuracy | Precision | Recall | F1-score |
|---|---|---|---|---|
| ID3 (Decision Tree) | 87.67% | 87.75% | 87.67% | 87.69% |
| Random Forest | 89.83% | 89.98% | 89.83% | 89.52% |
| MLP | **91.33%** | **91.86%** | **91.33%** | **91.35%** |

- **ID3** — most interpretable and cheapest to train, but the weakest generalization; some overfitting observed with deep trees.
- **Random Forest** — the most robust model to data variability (lowest variance across CV folds), with a good balance of performance and partial interpretability.
- **MLP** — best raw performance across every metric, at the cost of the highest training/inference compute and the least interpretability.

See Section 7 of the paper for the full comparative discussion, and Section 6 for the ethical considerations (algorithmic fairness, data bias, and privacy/LGPD compliance) raised by using these models in a clinical context.

## Getting started

```bash
git clone https://github.com/gUI-pe/classification-and-regression-study.git
cd classification-and-regression-study
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

Then open any of the notebooks (`decision-nb.ipynb`, `random.ipynb`, `mlp.ipynb`) in Jupyter, or run the standalone scripts directly:

```bash
python random-forest.py
python random-forest-scratch.py
```

> `mlp.ipynb` additionally requires `tensorflow`, which is not listed in `requirements.txt` — install it separately (`pip install tensorflow`) before running that notebook.
